# 受付スタンプ(社内イベント出欠管理)グレードアップ設計

日付: 2026-09-16
対象: claude.ai Artifact「受付スタンプ - 社内イベント出欠管理」
(https://claude.ai/artifact/TyjKsZTTPJA9mtbhiD7Piy)
ソース置き場: このリポジトリの `uketsuke-stamp/`

## 1. 背景と目的

現行アプリは「名簿を貼り付け → QR発行 → 各端末でスキャン → 端末ごとにCSV書き出し」の構成で、
受付記録は端末内(localStorage)にしか無く、名簿と受付が紐づいていない。

次回イベント(第48回改善事例発表会、2026-10-01 13:30、スクエア荏原 イベントホール)は
参加者 100 名超・受付端末 5 台で運用するため、以下を実現する。

1. 5 台の受付記録を 1 つに集約し、どの端末からも合計・未受付者がリアルタイムに見える
2. 部署別シートの Excel 出欠表をそのまま読み込める(貼り付け作業を無くす)
3. 個人情報(氏名・部署・役職)をクラウドに平文で置かない
4. イベント後、元の出欠表に貼り戻せる形の Excel と、受付一覧の CSV を書き出せる

## 2. 決定済みの前提

| 項目 | 決定 |
|---|---|
| 共有の置き場 | Artifact の `db` 機能(同一 claude.ai 組織のサインイン済みメンバーのみアクセス可) |
| 受付担当のアカウント | 5 名とも幹事と同じ組織の claude.ai アカウントを持つ |
| 個人情報の扱い | 氏名・部署・役職はパスフレーズ由来の鍵で暗号化してから共有DBに保存。平文で載るのは参加者ID・受付時刻・端末名・イベント名/日時/会場のみ |
| イベント数 | 常に「現在のイベント」1 つ。次回は「新しいイベントを開始」で全消去して使い回す |
| QR 発行対象 | 既定は「出欠席予定 = 〇」の人のみ(切替で全員も可) |
| 名簿の確定時期 | 取込時点で未確定。同じパスフレーズで再取込しても参加者IDが変わらない設計にする |
| 書き出し | CSV(受付一覧)と Excel(元の出欠表と同じシート構成)の両方 |

## 3. 入力 Excel の構造(実ファイルから確認済み)

- 部署シート: `01 役員` 〜 `３０ 大阪支店他` の 30 枚。シート名は「番号 + 空白 + 部署名」。番号は半角/全角が混在
- 対象外シート: `原本`(旧回のテンプレ)、`出欠合計表`、`Sheet2`、`Sheet3` — 「先頭が数字(半角/全角)+空白」に一致しないシートは読み飛ばす
- 各部署シートのレイアウト(共通)
  - 1 行目 A: イベント名(例: `第48回改善事例発表会出欠表`)
  - 2 行目 A: 日時(例: `2026年10月1日（木）　13:30　開始`)
  - 3 行目 A: 会場
  - 4 行目: 見出し。A=`氏　名`、G=`役職`、K=`出欠席予定`、N=`当日出欠席`、Q=`欠席理由`、AC=`備考`(各見出しは横に結合)
  - 5 行目以降: 名簿 1 人 1 行。A=氏名(A:F 結合)、G=役職、K=出欠席予定(`〇`/`×`/空欄)、N=当日出欠席(現在は全て空)
  - 小見出し行(例: `３０ 大阪支店他` の 5 行目「大阪支店・名古屋支店・仙台支店」)や末尾の注意書き行は **A 列が A:AK など全幅で結合**されている
  - 小計行は A 列が空で K/N に数値
- 名簿人数: 366 名(シートあたり 3〜23 名)

### 見出し行と列の特定(列位置を固定しない)

後任の幹事が Excel の列を動かしても壊れないよう、列は見出しラベルから特定する。

1. 各部署シートの 1〜10 行目を上から走査し、「氏名」「役職」「出欠席予定」の 3 ラベルが同じ行に揃う最初の行を見出し行とする。ラベル比較は空白(半角・全角)・改行を除去してから前方一致で行う(`氏　名` → `氏名`、`出欠席\r\n予定` → `出欠席予定`)
2. 見出し行で見つかった各ラベルの列を、氏名列 / 役職列 / 出欠席予定列とする。`当日出欠席` があればその列も記録する(書き出し時の貼り付け先案内に使う)
3. 見出し行が見つからないシートは読み飛ばし、プレビューに警告として表示する
4. イベント情報(title / dateText / venue)は、最初の部署シートの見出し行より上の行の A 列を順に(1 行目 → title、2 行目 → dateText、3 行目 → venue)取得し、幹事が編集できる

現行ファイルでは見出し行 = 4 行目、氏名 = A、役職 = G、出欠席予定 = K、当日出欠席 = N として解決される。

### 名簿行の判定ルール

見出し行の次の行以降について、次を全て満たす行を名簿行とする。

1. 氏名列のセルが文字列で空でない
2. その行の氏名セルを含む結合範囲が「氏名列〜役職列の手前」に収まる(全幅結合の行は小見出し/注意書きとして除外)
3. 氏名セルの長さが 20 文字以下(保険)

読み飛ばした行(全幅結合以外で条件に合わない行)はプレビューに警告として表示する。

### 取り込む項目

| 項目 | 取得元 | 正規化 |
|---|---|---|
| deptOrder | シート名先頭の番号 | 全角→半角、整数 |
| dept | シート名から番号と空白を除いた残り | 前後空白除去 |
| sheetName | シート名そのまま | — |
| row | 元の行番号(1 始まり) | — |
| name | 氏名列 | 前後空白除去。全角空白は保持(氏名の姓名区切り) |
| title | 役職列 | 前後空白除去、空可 |
| plan | 出欠席予定列 | `〇`/`○`/`◯`/`o`/`O`→`yes`、`×`/`x`/`X`/`✕`→`no`、その他/空→`unknown` |

名簿ブロックには、書き出し時に元の見出しを再現するため、部署シートごとの見出し行番号と `当日出欠席` 列の位置(例: `N`)も保持する。

## 4. 参加者 ID と暗号化

- 鍵導出: `PBKDF2-SHA256(パスフレーズ, salt, 200,000 回)` → 256 bit。`salt` は 16 byte 乱数で `event/current` に平文保存
- 暗号化: AES-GCM、IV 12 byte 乱数。保存形式は `base64(iv) + "." + base64(ciphertext)`
- パスフレーズ検証: `event/current.check` に `encrypt("uketsuke-ok")` を保存し、復号して一致すれば正しい
- 参加者 ID: `HMAC-SHA256(鍵, dept + "\u001f" + name + "\u001f" + n)` の先頭 16 hex 文字。`n` は同一 dept 内で同姓同名が出た場合の 0 始まり連番(元の行順)
  - 同じパスフレーズ・同じ dept・同じ氏名なら再取込でも同じ ID
  - パスフレーズ変更は提供しない(印刷済み QR が無効になるため)。変えたい場合は「新しいイベントを開始」
- QR の内容: `RS2:<ID>`(氏名は入れない)
- WebCrypto(`crypto.subtle`)を使用。Node.js 20+ でも同じ API が使えるためテスト可能

## 5. 共有DBのデータモデル

Artifact の `capabilities` 宣言:

```json
{
  "db": {
    "rules": [
      { "path": "", "read": "interact", "write": "admin" },
      { "path": "checkins", "read": "interact", "write": "interact" }
    ]
  },
  "downloads": true
}
```

- 「編集可」で共有された人(admin)= 幹事: 全ドキュメント書込可
- 「閲覧可」で共有された人(interact)= 受付担当: `checkins` 配下のみ書込可
- `user` 機能はこの環境では使えないため、画面側で役割を判定しない。幹事タブは全員に表示し、権限が無い操作は失敗時に「幹事権限(編集可の共有)が必要です」と表示する

| ドキュメント | 内容(平文) | 内容(暗号化) |
|---|---|---|
| `event/current` | `title`, `dateText`, `venue`, `salt`, `check`, `rosterVersion`(整数), `createdAt`, `updatedAt` | — |
| `roster/current` | `version`(整数), `count`, `updatedAt` | `blob` = `{ people: [{id, deptOrder, dept, sheetName, row, name, title, plan}], sheets: [{sheetName, deptOrder, headerRow, dayCol}] }` を JSON → 暗号化 |
| `checkins/<参加者ID>` | `pid`, `t`(ISO 8601), `dev`(端末名), `kind`(`qr`/`manual`), `v`(rosterVersion) | — |
| `checkins/w-<乱数>` | `pid`(= doc id), `t`, `dev`, `kind` = `walkin` | `enc` = `{name, dept}` を暗号化 |

- 名簿は 1 ドキュメント 1 ブロック(366 名で約 30 KB。上限 256 KiB に十分収まる)。購読は 1 本で済む
- 受付記録は参加者 ID をドキュメント ID にする。2 台が同時に同じ人をスキャンしても同じドキュメントへの上書きになり、二重登録にならない
- 取消 = ドキュメント削除
- 「新しいイベントを開始」= `event/current`, `roster/current` 削除 + `checkins` 全件削除(クエリで列挙して 1 件ずつ削除)

### 再取込時の扱い

- 名簿ブロックを丸ごと置換し `rosterVersion` を +1
- 受付記録は残す。名簿から消えた ID の記録は各画面で「名簿外」として表示し、Excel 書き出しでは「名簿外」シートに載せる

## 6. 同期とオフライン耐性(`sync.js`)

- 受付操作はまず端末内キュー(localStorage `uketsuke_pending_v2`)に積み、直後に共有DBへ `set`
- 成功したらキューから外す。失敗(`unavailable` など)はキューに残し、5 秒間隔で再送。画面に「未送信 n 件」を表示
- `checkins` コレクションを `onSnapshot` で 1 本購読し、全端末の記録をメモリに保持。画面はこのメモリから描画
- 「受付済みか」の判定は購読中のメモリ + 端末内キューの両方を見る
- 取消は `delete`。失敗時も同様にキューへ
- DB が `null`(未許可・読み込み失敗)の場合は「共有DBに接続できません」を表示し、受付操作を無効化する

## 7. 画面構成(`index.html` / `app.js`)

タブ: **幹事** / **受付** / **状況**。既存のデザイン(Noto Sans JP、赤いスタンプ、ライト/ダーク対応)は踏襲する。

### 幹事タブ

1. イベント設定 — イベント名 / 日時 / 会場(Excel から自動入力、編集可)。パスフレーズは未設定なら入力欄、設定済みなら「設定済み」表示のみ。設定済みなのにこの端末に鍵が無い場合(幹事が別 PC で開いた場合)は受付タブと同じパスフレーズ入力を求め、検証してから名簿の再取込・QR 発行・書き出しを許可する
2. 名簿取込 — ファイル選択 → 解析 → プレビュー(シート名 / 人数 / 〇 / × / 未回答、合計、警告) → 「名簿を共有DBに保存」。既に名簿がある場合は差分(追加 / 削除 / 予定変更の件数)を表示してから上書き。ファイルの中身は端末外に出ない(解析はブラウザ内)
3. QR 発行 — 対象「予定〇のみ」(既定)/「全員」。部署順・行順に QR カード(QR + 氏名 + 部署 + 役職)。「印刷」で QR カードのみ 3 列印刷
4. 書き出し — 「CSV」「Excel」(§8)
5. 新しいイベントを開始 — 確認ダイアログで「削除」と入力させてから全消去

### 受付タブ

1. 入口 — 名簿が無ければ待機メッセージ。名簿があり端末に鍵が無ければパスフレーズ入力(検証失敗なら再入力)。鍵は端末内(localStorage)に保存し「この端末から忘れる」で消せる
2. 端末名 — 任意文字列(例: `受付1`)。端末内保存
3. カウンター — 全端末合計「受付済 X / 予定〇 Y」
4. QR スキャン — 既存のカメラ枠と jsQR。結果に応じて
   - 名簿一致・未受付 → 赤「受付」スタンプ + 氏名・部署、記録
   - 受付済み → グレー「済」+「HH:MM 受付2で受付済み」
   - 名簿に無い ID → 「?」+「名簿にないQRです。名簿から検索してください」
   - 同じ QR の連続読取は 2.5 秒抑止(既存どおり)
5. 名簿から受付 — 検索欄(氏名の一部 / 部署名)→ 候補(氏名・部署・役職・予定・受付状態)→ タップ → 確認 → 記録(`kind: manual`)
6. 飛び入り追加 — 氏名・所属を入力 → 記録(`kind: walkin`、氏名は暗号化)
7. この端末の受付履歴 — 直近 20 件、「取消」付き。「未送信 n 件」バッジ

### 状況タブ

1. サマリー — 受付済 / 予定〇 / 未受付(〇なのに未)/ 予定外出席(× or 未回答 or 飛び入りで受付)
2. 部署別テーブル — 部署 | 予定〇 | 受付済 | 未受付 | 予定外。行タップで未受付者の氏名を展開
3. 受付履歴(全端末) — 新しい順、時刻・氏名・部署・端末・種別。「取消」可

### 判定ロジック(`core.js`)

| 予定 | 受付 | 判定 |
|---|---|---|
| yes | あり | 通常(空欄) |
| yes | なし | `未受付` |
| no / unknown | あり | `予定外出席` |
| no / unknown | なし | 空欄 |
| 名簿外(walkin または名簿から消えた ID) | あり | `名簿外` |

## 8. 書き出し(`core.js` でデータ生成、`app.js` で保存)

### CSV

- ヘッダ: `氏名,部署,役職,出欠席予定,受付時刻,受付端末,種別,判定`
- 受付した人のみ(飛び入り・名簿外含む)、受付時刻昇順
- 出欠席予定は `〇` / `×` / 空欄で出力、種別は `QR` / `名簿` / `飛び入り`
- BOM 付き UTF-8、CRLF、全フィールドをダブルクォート
- ファイル名: `受付一覧_<イベント名>_<yyyyMMdd_HHmm>.csv`

### Excel(.xlsx、SheetJS で生成)

- 部署シート: 元と同じシート名・順序。見出し行より上はイベント名 / 日時 / 会場、見出し行(元と同じ行番号)は `氏名 | 役職 | 出欠席予定 | 当日出欠席 | 受付時刻 | 受付端末 | 判定`。**見出し行の次以降は元ファイルと同じ行番号に同じ人を配置**し、名簿行でない行は空行にする(D 列をそのまま元の「当日出欠席」列に貼り付けられる)
- 各部署シートの見出し行の右側(I 列)に貼り付け先の案内を 1 セル入れる(例: `→ 元ファイルの N5:N27 に貼り付け`)。列と行範囲は名簿ブロックに保持した `dayCol` と名簿行の範囲から生成する
- 当日出欠席: 受付済みなら `〇`、それ以外は空欄
- `名簿外` シート: 飛び入り・名簿から消えた ID の一覧(氏名 | 所属 | 受付時刻 | 受付端末)
- `集計` シート: 部署 | 予定〇 | 受付済 | 未受付 | 予定外 と合計行
- 書式(罫線・結合・マクロ)は複製しない
- ファイル名: `当日出欠_<イベント名>_<yyyyMMdd_HHmm>.xlsx`

保存は `downloads` 機能を優先し、使えない場合は `<a download>` にフォールバック(既存どおり)。

## 10. エラー処理

| 状況 | 挙動 |
|---|---|
| Excel に部署シートが 1 枚も無い | 「部署シート(番号+部署名)が見つかりません」 |
| 名簿保存で権限エラー(`invalid_argument`) | 「幹事権限(編集可の共有)が必要です」 |
| パスフレーズ不一致 | 「パスフレーズが違います」、再入力 |
| DB が null | 受付・状況タブに「共有DBに接続できません」、操作無効 |
| 書込失敗(`unavailable` 等) | キューに残して再送、「未送信 n 件」 |
| `quota_exceeded` | トーストで表示(受付記録は最大でも数百件なので実質発生しない) |
| カメラ起動失敗 | 既存どおりトースト |

## 11. テスト

- 実行: `node --test uketsuke-stamp/tests/`
- `core.test.js`
  - 固定ファイル(30 シート、全角番号、小見出し行、小計行、注意書き行を含む)から 366 件相当の名簿と警告 0 件が得られる
  - 対象外シートを読み飛ばす
  - 見出しラベルによる列特定: 列を入れ替えたシート(例: 役職 → 氏名 → 出欠席予定の順)や見出し行が 6 行目にあるシートでも正しく読める。見出し行が無いシートは警告付きで読み飛ばす
  - `plan` の正規化(〇/○/◯/×/x/空欄)
  - 同姓同名の連番と ID の決定性(同じ入力 → 同じ ID、パスフレーズが違えば別 ID)
  - 暗号化→復号の往復、誤パスフレーズで検証失敗
  - 判定ロジックと部署別集計
  - CSV 文字列(BOM、クォート、順序)
  - Excel 用データ(行番号の整合: 元の行 r の人が出力の行 r にいる、名簿外・集計シート)
- `sync.test.js`(メモリ上の偽 DB)
  - 2 台が同じ ID を書いても 1 件
  - 書込失敗 → キュー保持 → 復帰で再送・キューが空になる
  - 取消で削除される
  - 購読で他端末の追加が反映される
- 手動確認(公開後): ダミー名簿で取込 → QR 発行 → 名簿から受付 → 状況タブ → CSV/Excel 書き出し。カメラ読取は実機

- 受付担当ごとのログイン/権限の細分化(閲覧可 / 編集可の 2 段階のみ)
- 旧形式 QR(v1 JSON)の読み取り互換
- Artifact の所有権譲渡(claude.ai 側に操作が無いため。§13 の再公開手順で代替)

## 13. 幹事の交代と引き継ぎ(`uketsuke-stamp/README.md` に記載する内容)

### 幹事担当者が変わる(Artifact 所有者は同じ)

- 所有者が新しい幹事に Artifact を「編集可」で共有する。それだけで名簿取込・QR 発行・イベントリセット・書き出しが行える
- 受付担当には「閲覧可」で共有する
- パスフレーズはイベントごとに新規設定するため、前任者から引き継ぐ必要はない。イベント途中の交代時のみ口頭で伝える
- 幹事 PC が変わった場合はパスフレーズを入力すれば続きから操作できる

### Artifact の所有者が変わる(異動・退職など)

- 所有権の譲渡はできないため、後任者が自分の Artifact として再公開する。手順:
  1. このリポジトリを取得し、Claude Code で `uketsuke-stamp/` を開く
  2. `index.html` / `core.js` / `sync.js` / `app.js` を Artifact として公開する(`capabilities` は §5 の宣言をそのまま使う。README に公開時に Claude Code へ伝える文面を載せておく)
  3. 新しい URL を受付担当に共有し直す
- データはイベントごとに消す前提なので、旧 Artifact から移すデータは無い。旧 Artifact は所有者が削除する

### 毎回のイベントで行うこと(運用手順)

1. 幹事: 「新しいイベントを開始」で前回分を消去(消す前に CSV / Excel を書き出して保管)
2. 幹事: Excel を取り込み、パスフレーズを設定して名簿を保存
3. 幹事: QR を発行・印刷し、名札などに添付
4. 受付担当: 各端末で Artifact を開き、パスフレーズと端末名を入力
5. 当日: 受付タブでスキャン。状況タブで全体を確認
6. 終了後: 幹事が CSV / Excel を書き出し、Excel の「当日出欠席」列を元の出欠表に貼り付け
